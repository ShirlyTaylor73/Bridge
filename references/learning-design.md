# 学习设计

课程要回答的问题是：**当 AI 提交这项改动时，用户能否看懂它动了什么、判断它是否正确。** 不以用户能亲手写出实现为目标，不出编码作业。

## 从目标逆向设计

1. 先写结业任务：对这项改动，用户应能提出怎样的变更蓝图，应能在审查中发现哪些类型的问题。
2. 推导能力：每项能力对应一种具体的审核判断，写进 `decision`。写不出判断的内容不设能力。
3. 能力图只保留结业任务依赖的部分。常见但与本次判断无关的内容放进“不学”清单，并说明原因。
4. 按依赖排课。每课围绕少量能力，以仓库中的真实代码为材料。

通用背景知识（例如某类网络结构）只讲到足以判断本仓库中的接口、shape 与行为为止。目标需要的结论无法从目标仓库源码或可靠知识中确认时，在大纲中说明边界，不虚构代码事实。

## 控制时长

每课控制在用户一次能完成的规模，通常 15–25 分钟：讲义证据少而关键，正式题 3–5 道，开放题通常不超过 2 道。内容放不下时拆课或收窄范围。全课程课数过多时先回到“不学”清单。

## 出题规则

- 每道题对应一项能力，答错能说明用户缺少哪种审核判断。
- 正式题中至少一半属于应用或分析层：把理解用到具体输入、改动或故障上。单纯复述不算。
- 禁止考名称记忆：不问“某个类、函数、参数叫什么”，不依赖背诵行号。`locate` 题描述行为或职责，让用户找到实现它的位置，答题时可以查阅代码。
- 题面自足且只有可判定的答案；不在题面、`items` 顺序、diff 注释或标识符名称中泄露答案。`items` 以打乱后的顺序给出。
- 每课写 1–2 道跳课测。它独立于正式题，覆盖本课核心判断，答对足以说明可以跳过本课；用户可选择是否作答。
- 结业的变更蓝图要求用户预测真实目标改动涉及的文件、接口、shape 与验证方式；审查演练给出一份完整、可信的模拟改动。

| 题型 | 适合考察 | 注意 |
| --- | --- | --- |
| `locate` | 知道某项行为在哪里发生、改哪里才生效 | 范围取最小的关键代码段 |
| `order` | 调用链、数据流、初始化与清理顺序 | 顺序须由代码唯一确定 |
| `predict` | shape、返回值、分支走向 | 给出具体输入；提供 `refs` |
| `explain` | 机制与不变量 | rubric 列出必须说到的因果关系 |
| `design` | 取舍与约束 | rubric 评判理由，接受多种可行方案 |
| `forecast` | 改动波及面 | rubric 区分必改项、可能受影响项与无需改动项 |
| `review` | 发现模拟改动中的缺陷 | 见下节 |

除 diff 题外，每题尽量提供 `refs`；`predict` 必须提供。它们既是批改依据，也让过期检查能发现源码变化。

## 审查演练的风险

- 风险须是这类改动中**真实可能发生**的错误，并能依据仓库代码说清触发条件与后果，例如接口或 shape 不匹配、遗漏调用方、配置未同步、权重加载静默跳过、训练与推理分支不一致、设备或类型处理错误。
- 不用明显的语法错误、拼写错误或风格问题充数。
- diff 其余部分应当合理可信，让用户需要真正阅读与追踪才能发现问题。
- diff 中不加提示缺陷位置的注释。
- 保持原文件格式，只改动必要的行，像一次真实提交那样逐行手写 hunk。不要用序列化或格式化工具（如重新输出 JSON）改写整个文件：格式噪音会淹没真正的改动，也不像可审查的提交。
- 结业审查的风险不应与变更蓝图 rubric 要求说出的要点相同。蓝图考“该改哪里”，审查考“改了却改错或漏了什么”，例如实现细节、边界输入、静默失败等蓝图写不出来的问题。
- 结业审查的 diff 应覆盖这项改动实际涉及的文件，例如新建模块、注册与配置一起出现，风险分布在不同文件和层次。单题的 diff 只取能说明问题的文件。

写完后逐条核对：风险在当前代码上确实成立吗？还有没有未登记的真实缺陷？有的话补入 `risks` 或修正 diff。

## 提示与评分

- 三级提示：第一级指出思考方向或应查看的区域；第二级缩小到关键机制或对象；第三级给出接近答案的推理步骤，仍把结论留给用户。
- rubric 每条是一个可判断“有或无”的要点。覆盖全部关键要点记 `correct`，抓住主干但遗漏要点记 `partial`，未抓住主干记 `missed`。措辞不同不扣分。
- 审查题按发现的风险评分：能指出位置并说清后果才算发现。用户提出登记之外的问题时，依据代码核实，成立就认可。

## 答案可信度

出题前阅读相关源码，不凭文件名或常识推断行为。探针只用于验证可小规模复现的结论，例如在 CPU 上用小输入打印 shape；未实测的结论如实标 `derived`。
