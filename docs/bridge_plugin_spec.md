# Bridge 多客户端插件交付规格

> 此文保留 0.1 版本设计记录。当前实现以 [0.2.0 主题探索规格](bridge_explore_spec.md) 为准。

## 目标与边界

将项目级 Skill 升级为根目录可安装插件。保持现有扫描、语义分析、证据校验和静态 HTML 输出；不引入多子 Agent、MCP 服务或启动 hooks。插件与 Skill 名称均为 `bridge`，版本 `0.1.0`，仅依赖 Node.js 标准库，安装器最低 Node.js 22。

## 内容与客户端

共享内容迁移至 `skills/bridge/`，删除旧 `.agents/skills/bridge` 入口。脚本、参考资料和模板保持相对布局；插件安装位置与目标仓库位置严格分离。根目录 Agent Plugins 声明为基础，必要时增加宿主专有声明。所有路径必须在包内，所有声明身份与版本一致。

原生接入：Claude Code、Codex、Cursor、Copilot CLI、VS Code Copilot、Gemini CLI、Pi Agent、OpenClaw、Kimi Code。使用宿主安装、更新、卸载机制；旧版缺少支持时提示升级，不静默链接 Skill。

脚本接入：OpenCode、Antigravity、Vibe、Hermes、Cline、Trae、Nanobot、Kiro。两个薄入口 `install.sh`、`install.ps1` 共用 Node.js 实现与平台配置，分别使用目录软链接和 Windows junction；只安装用户级、单一 bridge 入口。Kiro 增加独立 bridge agent 配置，不覆盖现有配置。

平台配置记录发现目录、原生指引、参考来源和验证状态。首次以参考仓库 e24fcf6 的平台覆盖为基准，原生机制以当前官方文档为准。

## 安装生命周期

脚本默认来源为脚本所在仓库，支持 `--source`、`--uninstall`、`--list`、`--dry-run`、`--help`。用户先克隆或下载，不提供远程引导器。Git 来源由用户 `git pull --ff-only` 更新；归档来源原位替换后重装。

重复安装幂等；拒绝覆盖实体目录和不属于本工具的链接。记录安装来源与入口；卸载前核对归属，仅移除自己创建的入口，不删除源文件。来源移动可在显式 `--source` 重装时更新已登记入口。损坏状态不得按“无记录”处理；失败清晰退出。dry-run 不创建目录、链接或状态。

## 验证与验收

- 校验声明、版本和包内引用；迁移后从独立包目录扫描、校验、渲染外部目标。
- 同一固定分析数据使用迁移前后渲染器比较 HTML，确认模板和逻辑无变化。
- Node.js 内置测试覆盖安装、重复安装、卸载、断链、来源移动、冲突、中文及空格路径、Windows junction；只用临时目录。
- 三系统 CI 执行自动测试；未实际运行的系统不得声称通过。
- Claude、Codex、Kimi 原生安装后在新会话调用并完成真实分析；另选脚本客户端验证发现。保留 RPent d903f38 样本及页面交互验收要求。环境、账号或能力阻塞必须如实记录。
- 报告区分声明检查、安装测试和真实运行；未实测平台标记“适配已实现，客户端运行未验证”。

## 实施与版本管理

1. 固化规格并修订旧交付约束。
2. 迁移共享内容、原生声明与校验，阶段提交。
3. 实现兼容安装器、聚焦测试及三系统 CI，阶段提交。
4. 真实验收、更新 README/AGENTS/安装文档，复核本规格并提交。

仅支持仓库和本地安装，不涉及官方上架；发布仓库为 `https://github.com/ShirlyTaylor73/Bridge`，用户安装说明使用真实地址。插件迁移阶段保留 README 原有未提交修改；首次发布时一并纳入当前 README。实施允许在独立临时客户端配置中安装测试，避免更改用户日常安装状态。
