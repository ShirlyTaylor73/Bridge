# course / tutor 开发周期

长期目标：在用户让 AI 改代码之前和之后，帮助用户建立足以理解并审核改动的能力。各周期单独澄清需求、写规格、制定计划后实施。

| 周期 | 范围 | 状态 |
| --- | --- | --- |
| C1 | `course` 与 `tutor` 两个 Skill：仓库目标驱动的“出课 → 对话答题 → 批改 → 结业”最小闭环 | 实施中，见 [C1 规格](course_tutor_spec.md) |
| C2 | 资料库 | 未开始 |
| C3 | Dashboard 课程视图 | 未开始 |
| C4 | 开发流程编排 | 未开始 |

## C1 出课与上课闭环

课程来自目标仓库的真实源码与 explore 主题，对话作答，进度保存在目标仓库 `.bridge/courses/`，以“变更蓝图 + 审查演练”结业。

## C2 资料库

- 论文与参考代码下载。
- 固定学习工作区 `~/BridgeStudy/<topic>/`。
- 纯知识类目标（不依附某个目标仓库）。
- 论文证据校验。

## C3 Dashboard 课程视图

- 在页面中查看课程、讲义入口与进度。C1 不修改页面资产。

## C4 开发流程编排

理解缺口门禁 → 小课程 → 用户自拟计划 → AI 完善 → 执行 → 人类审核。C1 在进度中保存的结业原文（变更蓝图与审查发现）用于回填计划。

## 暂不排期

编码作业、沙箱 worktree、真实应用 diff、间隔复习调度。
