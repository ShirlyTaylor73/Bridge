# Bridge 0.2.0 按主题持续探索规格

## 已确认目标

`bridge` 建立完整文件树与职责；`explore` 根据具体问题新增或深化独立主题。首次探索提示先初始化。网页采用固定 HTML/CSS/JS 框架，通过本地 HTTP 服务按需读取 JSON。

## 独立存储与主题发现

`.bridge/base/{scan,tree}.json` 保存基础数据；`explorations/index.json` 记录主题 ID、标题、摘要、关键词、路径与更新时间；每个 `<主题-id>.json` 自包含问题、生成时间、commit、阶段、源码证据和注释。主题 ID 用有语义的英文 kebab-case，例如 training-pipeline，标题使用中文。证据 ID 在各主题内部独立。

每次探索先读索引；明确指定或延续已有主题时更新该主题，歧义时列出候选请用户选择；新主题追加，名称冲突时细化语义。只对本次探索检查源码，其他主题结果保持原样。探索可引用基础树生成后新增的文件，遵守扫描排除规则。

新增仅写新主题和索引；显式更新沿用主题 ID，先备份旧版本至 history/<主题-id>/。发布脚本负责校验、短时写锁、重新读取索引、原子替换与失败恢复；候选先保存于 .bridge 下的临时目录。普通探索保持页面资产、基础数据和旧主题文件内容不变。

再次运行 bridge 默认打开已有页面；显式刷新基础树才更新基础数据。初始化或明确页面升级时更新页面资产。本版按全新安装验收。

## 界面与服务

侧栏可按主题标题、摘要、关键词搜索；选择时加载主题文件，显示该主题自己的 commit 和时间。刷新重新读取数据；某个主题加载失败时其他入口可访问。

服务命令：node <插件目录>/scripts/serve-dashboard.mjs <目标仓库> [--port <端口>]。Node.js 标准库，绑定 127.0.0.1，默认随机可用端口；仅提供 .bridge 内文件，检查 URL 解码与真实路径，数据禁用缓存。

目录展开状态由目录 ID 集合保存，node.open 只用于初始化。点击文件只更新高亮和职责面板；全部收起覆盖默认展开目录。搜索临时展开匹配路径，清空后恢复手动状态；跨视图保留基础树状态、滚动位置和窄屏抽屉交互。

## 交付与实现顺序

共享脚本在 scripts/，页面在 assets/，契约在 references/。skills/bridge 与 skills/explore 引用同一套资源。兼容安装器成组安装两个 Skill，通过真实路径解析定位共用资源，Kiro 注册两个入口。所有版本声明统一 0.2.0。

阶段：1. 规格和基础存储/服务；2. 双 Skill 和探索发布；3. 页面状态与安装；4. 聚焦测试、客户端与浏览器验收、文档。各阶段检查 diff 并提交。

## 验收

- 初始化空主题；未初始化探索提示；主题发现和歧义确认。
- 新增主题前后旧主题、基础树、页面资产哈希相同；修改旧源码后新增其他主题仍不变。
- 更新选定主题产生备份；相同证据 ID 可跨主题；并发发布索引完整。
- 无效证据与写入失败保持旧结果可访问；服务路径边界和中文空格路径正确。
- 浏览器检查嵌套目录选择、全部收起、搜索恢复、切换视图、窄屏及主题加载失败。
- 客户端运行 bridge、两次新增 explore、一次主题更新；独立安装副本发现双 Skill 和共享资源。

完成后复核本规格并记录实际运行结果。
